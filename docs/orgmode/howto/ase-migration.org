* Migrate from ase.optimize

~rgmin.optimize~ has the ~ase.optimize~ class names. Change the import and keep the rest of the script.

#+begin_src python
from ase.build import add_adsorbate, fcc111
from ase.calculators.emt import EMT
from ase.constraints import FixAtoms
from rgmin.optimize import BFGS  # was: from ase.optimize import BFGS

slab = fcc111("Cu", (3, 3, 4), vacuum=8.0)
add_adsorbate(slab, "O", 1.2, "fcc")
slab.set_constraint(FixAtoms(indices=[a.index for a in slab if a.tag >= 3]))
slab.calc = EMT()
opt = BFGS(slab, trajectory="relax.traj", logfile="relax.log")
converged = opt.run(fmax=0.01, steps=200)
#+end_src

Every class is an ~ase.optimize.optimize.Optimizer~. ~run(fmax, steps)~ and its return value, ~irun~, ~converged()~, ~nsteps~, ~attach~, the log line, the trajectory frames and ~todict~ are ASE's own code. The classes read and move the system only through ~self.optimizable~. ~FrechetCellFilter~, ~UnitCellFilter~, ~ExpCellFilter~ and ~StrainFilter~ therefore work as with ASE, and so do ~FixAtoms~, ~FixedLine~, ~FixCartesian~ and ~FixedPlane~. Importing ~rgmin~ does not import ASE; the classes load on first use.

** Classes

| rgmin class | ASE class | against ASE on the same start |
|---+---+---|
| ~BFGS~ | ~BFGS~ | same iterates to rounding until a pair with ~s·y <= 1e-12~ |
| ~LBFGS~ | ~LBFGS~ | same iterates to rounding at ~damping=1~ |
| ~FIRE~ | ~FIRE~ | same iterates to rounding; ~downhill_check~ resets differ |
| ~FIRE2~ | ~FIRE2~ | Guénolé 2020 FIRE 2.0; different iterates |
| ~LBFGSLineSearch~ | ~LBFGSLineSearch~ | rgmin's strong Wolfe search; different iterates |
| ~SR1~, ~SR2~, ~SteepestDescent~, ~BarzilaiBorwein~, ~Adam~ | none | rgmin only |
| ~CG~, ~PolakRibiere~, ~FletcherReeves~, ~HestenesStiefel~, ~DaiYuan~, ~ConjugateDescent~, ~HagerZhang~, ~LiuStorey~, ~FRPR~, ~EonCG~ | none | rgmin only, no line search |
| ~NewtonCG~, ~NewtonPCG~ | none | rgmin only, finite-difference Hessian products |

"Same iterates" means the same positions to 1e-8, the same ~nsteps~, the same number of calculator calls, and the same log lines and trajectory frames. ~python/tests/test_ase_conformance.py~ checks this on a rattled Au8 cell, a Cu(111)+O slab under each constraint, and Cu vacancy cells in each cell filter.

~BFGS~, ~LBFGS~, ~LBFGSLineSearch~, ~FIRE~ and ~FIRE2~ take ASE 3.29's constructor arguments, in ASE's positional order and with ASE's defaults: ~restart~, ~logfile~, ~trajectory~, ~append_trajectory~, ~maxstep~ (and ~FIRE~'s deprecated ~maxmove~), ~alpha~, ~memory~, ~damping~, ~use_line_search~, ~dt~, ~dtmax~, ~dtmin~, ~Nmin~, ~finc~, ~fdec~, ~astart~, ~fa~, ~a~, ~downhill_check~, ~position_reset_callback~, ~use_abc~, plus ~master~ and ASE's other keyword arguments. The rgmin-only classes take ~maxstep~ (longest atomic displacement, default 0.2), ~alpha~ (initial Hessian guess, default 70, so the first step is ~-g / alpha~) and ~accept~ (~"energy"~, ~"none"~ or ~"nonmonotone"~). ~Adam~ divides out the gradient's scale, so ~alpha~ does not size its step; its ~learning_rate~ (default 0.02) is how far each coordinate moves per step.

ASE's ~ODE12r~, ~GPMin~, ~MDMin~, ~BFGSLineSearch~ (~QuasiNewton~), ~GoodOldQuasiNewton~, ~CellAwareBFGS~ and ~RFO~ have no rgmin class. rgmin has no ODE12r integrator and no Gaussian-process minimizer. Its RFO, Newton and dogleg steps need a dense Hessian, which an ASE calculator does not supply. Its scaled conjugate gradient is a whole-run function (~minimize_scg~), not a one-step session, so it cannot drive an ASE ~Optimizer~ either.

** Differences

Each difference has a test in ~python/tests/test_ase_conformance.py~ that shows where the two packages part.

- ~BFGS~ skips a pair with ~s·y <= 1e-12~ in the scaled energy. ASE updates the Hessian anyway and steps along its absolute eigenvalues.
- ~LBFGS~ multiplies ~maxstep~ by ~damping~. ASE multiplies the step after the cap, so with ~damping < 1~ ASE also damps a step shorter than ~maxstep~. ~LBFGS~ drops a pair with too little curvature and clears the memory after a direction that is not descent. ASE keeps both. ~use_line_search=True~ is rgmin's strong Wolfe search, not ASE's ~LineSearch~ with ~c1=0.23~ and ~c2=0.46~. ~eon_cap=True~ selects the rgmin default step instead of ASE's length control.
- ~FIRE~ with ~downhill_check=True~ keeps the time step after a reset, where ASE halves it. The next kick uses the force at the restored point, where ASE reuses the force of the refused one. ~a~ other than ~astart~ warns.
- ~FIRE2~ follows Guénolé et al. 2020. The time step floor is ~0.02 * dt~, so ~dtmin~ other than ASE's default ~2e-3~ at ~dt=0.1~ is a ~ValueError~. The first ~Nmin~ steps hold ~dt~, and 2000 consecutive uphill steps stop the session.
- A ~restart~ file holds the evaluations rgmin made, not ASE's arrays. The same class on that file replays them through a fresh session without calling the calculator, so a run continues where it stopped. An ASE restart file, a file from another class, or a file that no longer matches the system raises ~ase.optimize.RestartError~.
- On a ~StrainFilter~ cell the classes without curvature or a line search (~SteepestDescent~, ~EonCG~, ~HagerZhang~, ~LiuStorey~) reach the relaxed energy but approach ~fmax=0.01~ slowly. A ~learning_rate~ near ~maxstep~ makes every ~Adam~ step a capped sign step, which climbs out of the start basin, walks off the strain coordinates, and ends where the last bits of the forces send it.

** Benchmark

~python benches/ase_optimize.py~ runs both packages at their defaults on EMT Cu55 and Pt38 clusters, Cu(111)+O and Pt(111)+O slabs with the two bottom layers fixed, an LJ38 cluster, and a 107-atom Cu vacancy cell in a ~FrechetCellFilter~. Each row is five serial repeats with fmax 0.01 and a 2000-step budget. Steps and calculator calls were the same on every repeat. Wall time is the median of the whole ~run~, calculator included. EMT and ~LennardJones~ are Python, so most of the time is spent in the calculator. The full table, with energies and final forces, is ~benches/ase_optimize/results.md~.

Run at commit 1f6d190 with rgmin 0.2.0, ASE 3.29.0, NumPy 2.5.4 and Python 3.12.3, on Linux 6.12 ~x86_64~ (Intel Xeon, 8 logical CPUs).
