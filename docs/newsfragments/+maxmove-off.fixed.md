A `Control::maxmove` or `Solver::set_maxmove` value that is not a positive finite length is no Euclidean cap on every path that reads it: the dogleg, Newton-CG and Newton-PCG trust ceilings in a session and in `minimize_method_hess`, `minimize_method_hvp` and `minimize_newton_cg`, the constrained trust step and clips, the FIRE fill of `Solver::run_fill`, and every step clip. Before, such a value pinned the session trust ceiling at the current radius, so the radius never grew, and pinned the `minimize_newton_cg` ceiling at its radius floor. `-inf` broke the constrained runs of steepest descent, nonlinear CG and QuickMin. The FIRE fill scaled a step by `cap / |step|`, so a negative cap reversed it and the run climbed, from 30.1 to 125 in six steps under `-1`. A negative or infinite value still turns the default per-atom cap off, and zero and NaN still keep it. The C `rgmin_solver_set_maxmove` reaches the same session paths and is fixed with them. The C signatures and ABI minor 43 are unchanged.
